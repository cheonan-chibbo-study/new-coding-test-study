# 다리를 지나는 트럭

## 문제 분석

- 길이 `bridge_length`, 하중 `weight` 인 다리를 트럭이 순서대로 건넌다. **추월은 없다.**
- 트럭은 1초에 1칸씩 움직이고, 다리 위 트럭 무게의 합이 `weight` 를 넘을 수 없다.
- 모든 트럭이 다리를 **완전히 건너는** 데 걸리는 최소 시간을 구한다.
- 핵심 관찰 두 가지
  - 다리 위에는 **정확히 `bridge_length` 칸**이 있고, 매 초 전체가 한 칸씩 밀린다. → 길이가 고정된 큐다.
  - 트럭이 다리에 올라간 뒤 `bridge_length` 초가 지나면 반드시 내려온다. → 언제 내려오는지는 올라간 순간 결정된다.

## 풀이 고민

### 자료구조/알고리즘 후보
- 선택지 A : 다리를 `bridge_length` 크기의 큐로 두고, 빈 칸을 `0` 으로 채워 1초씩 시뮬레이션
- 선택지 B : 다리 위 트럭만 `(무게, 내려오는 시각)` 쌍으로 큐에 넣고, 시간을 건너뛰며 시뮬레이션

### 선택지 A 설명

다리를 길이 `bridge_length` 짜리 큐로 만들고 처음엔 전부 `0`(빈 칸)으로 채운다.
매 초마다
- `time++`
- 큐 맨 앞을 `poll()` 해서 합계 `sum` 에서 빼고 (다리를 벗어난 칸)
- 다음 트럭을 올릴 수 있으면(`sum + next <= weight`) 올리고, 못 올리면 `0` 을 넣어 빈 칸을 밀어 넣는다

큐 크기가 항상 `bridge_length` 로 유지되므로 "몇 칸째 있는지"를 따로 관리할 필요가 없다.
자리 이동 자체가 `poll` + `offer` 한 쌍으로 표현된다.

종료 조건은 `idx < truck_weights.length || sum > 0` 이다.
올릴 트럭이 남았거나, 다리 위에 트럭이 아직 있으면 계속 돈다.

### 선택지 B 설명

빈 칸을 큐에 넣지 않고, 다리 위 트럭만 `(무게, 내려오는 시각)` 으로 들고 있는 방식이다.
아무 일도 일어나지 않는 초를 통째로 건너뛸 수 있어서 `bridge_length` 가 아주 커도 시간이 늘지 않는다.

대신 "지금 시각", "맨 앞 트럭이 내려오는 시각", "다음 트럭을 올릴 수 있는 가장 이른 시각"을 직접 계산해야 해서
시간 계산 로직이 코드 밖으로 드러나고, 경계 처리에서 실수하기 쉽다.

## 최종 결정 및 근거

**선택지 A (0으로 패딩한 고정 길이 큐) 를 선택했다.**

### 왜 빈 칸을 `0` 으로 채우는가

빈 칸을 `0` 으로 두면 "무게 0짜리 트럭"과 똑같이 다룰 수 있다.
`sum` 에 더하고 빼도 값이 변하지 않으므로, 빈 칸인지 트럭인지 구분하는 분기가 아예 사라진다.
큐 길이가 항상 `bridge_length` 라는 불변식도 이걸로 유지된다.

### 왜 `sum` 을 따로 들고 있는가

다리 위 무게 합은 매 초 확인해야 하는 값이다.
매번 큐를 순회해서 더하면 초마다 `O(bridge_length)` 가 들지만,
올릴 때 더하고 내릴 때 빼는 식으로 관리하면 `O(1)` 이다.
큐와 `sum` 은 항상 같이 갱신해야 하는 한 쌍이라, 넣고 빼는 자리마다 짝을 맞췄다.

### 왜 시간을 건너뛰지 않았는가

제약이 `bridge_length <= 10,000`, 트럭 수 `<= 10,000` 이다.
최악이어도 `time` 은 `트럭 수 + 다리 길이` 수준이라 1초 단위 시뮬레이션으로 충분하다.
선택지 B의 시간 계산은 이 규모에서 얻는 이득보다 실수할 여지가 더 크다고 판단했다.

| 기준 | A: 0 패딩 고정 큐 (선택) | B: (무게, 내려올 시각) 큐 |
| --- | --- | --- |
| 시간 복잡도 | `O(트럭 수 + 다리 길이)` | `O(트럭 수)` |
| 큐에 들어가는 원소 | 빈 칸 포함 전부 | 다리 위 트럭만 |
| 분기 처리 | 빈 칸/트럭 구분 없음 | 시각 비교 분기 필요 |
| 실수할 여지 | 낮음 | 시각 경계에서 off-by-one 나기 쉬움 |
| 현재 제약에서 | 충분함 | 과한 최적화 |

## 회고

### 검증

| 입력 | 기댓값 | 결과 |
| --- | --- | --- |
| `bridge_length=2, weight=10, [7,4,5,6]` | 8 | 통과 |
| `bridge_length=100, weight=100, [10]` | 101 | 통과 |
| `bridge_length=100, weight=100, [10,10,10,10,10,10,10,10,10,10]` | 110 | 통과 |

### 배운 점

- "1초마다 한 칸씩 민다"를 큐의 `poll` + `offer` 한 쌍으로 옮기니, 위치를 따로 계산하는 코드가 전부 사라졌다.
- 빈 칸을 `0` 으로 표현한 게 이 풀이의 핵심이다. 특수 케이스를 값으로 흡수하면 분기가 사라진다.
- 종료 조건을 "올릴 트럭이 남았다 **또는** 다리 위에 트럭이 있다"로 잡아야 한다. 앞의 조건만 보면 마지막 트럭이 다 건너기 전에 멈춘다.
