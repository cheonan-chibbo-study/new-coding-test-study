# 숫자 게임

## 문제 분석

- 길이가 같은 두 배열 `A`, `B` 가 있고 라운드마다 카드를 한 장씩 낸다. **B의 카드가 더 클 때만 B가 이긴다.**
- 카드를 내는 순서는 자유롭게 정할 수 있다. 즉 "몇 번째 라운드인지"는 의미가 없고, **A와 B를 어떻게 짝지을 것인가**의 문제다.
- **같은 값은 무승부이지 승리가 아니다.** 비교는 `>` 이고 `>=` 가 아니다.
- `n` 은 최대 `100,000` 이다. `O(n^2)` 은 약 `10^10` 번 연산이라 시간 초과다.
- 핵심 관찰: 어떤 A를 이기기로 정했다면, 그 A를 이기는 B 중 **가장 작은 카드**를 쓰는 게 항상 이득이다. 큰 카드는 뒤에 나올 더 큰 A를 위해 아껴야 한다.

---
## 풀이 고민

### 자료구조/알고리즘 후보
- 선택지 A : A를 하나씩 돌면서 그 A를 이기는 B 중 최솟값을 매번 탐색 (이중 반복문)
- 선택지 B : A, B를 오름차순 정렬한 뒤 포인터 하나로 훑기 (그리디)

### 선택지 A 설명

A를 하나씩 꺼내고, 남아 있는 B 전체를 훑어 그 A를 이기는 최솟값을 찾는 방식이다.
문제를 그대로 옮긴 형태라 정확성은 의심할 여지가 없다.

문제는 **이미 쓴 카드를 다시 고르지 않도록 사용 여부를 따로 관리해야 한다는 점**이다.
`boolean[] used` 를 두거나 `ArrayList.remove` 로 지워야 하는데, 전자는 이미 쓴 칸까지 계속 다시 훑고 후자는 삭제 자체가 `O(n)` 이라 결국 같다.

비용은 라운드마다 `O(n)`, 전체 `O(n^2)`. `n = 100,000` 이면 약 `10^10` 번이라 통과할 수 없다.
사용 여부 관리 코드까지 붙으면 길이도 길어져서 접었다.

### 선택지 B 설명

선택지 A에서 낭비를 발견한 지점이 그대로 개선점이 된다.
문제에서 A와 B의 길이가 같다고 했으니, **두 배열을 오름차순으로 정렬해 두면 "A를 이기는 B 중 최솟값"이 앞에서부터 순서대로 나온다.**
매번 탐색할 필요 없이 포인터 하나면 같은 일을 할 수 있다.

인덱스 두 개만 들고 한 번 순회한다.
- `i` : B를 훑는 인덱스 (반복문 변수)
- `idx` : A에서 아직 지지 않은 카드 중 최솟값을 가리키는 인덱스

각 B에 대해
1. `A[idx] < B[i]` 이면 이 짝을 확정하고 `idx++`, `answer++`
2. 아니면 이 B는 버리고 `i` 만 넘어간다 (`idx` 는 그대로)

정렬 `O(n log n)` + 선형 스캔 `O(n)` = **`O(n log n)`**, 추가 공간은 정렬을 제외하면 `O(1)` 이다.

## 최종 결정 및 근거

**선택지 B (양쪽 정렬 + 포인터 그리디) 를 선택했다.**

자료구조는 `int` 배열과 `Arrays.sort` 만 썼다.
정렬된 배열에서 "남은 것 중 최솟값"은 항상 포인터 위치이므로 `PriorityQueue` 나 `HashMap` 같은 게 필요 없다.

### 지금 B가 남은 A 중 최솟값도 못 이기면, 다른 A는 이길 수 있는가

없다. A가 오름차순이므로 `A[idx]` 는 남아 있는 A 중 최솟값이고, 나머지 남은 A는 전부 `A[idx]` 이상이다.
따라서 `B[i] <= A[idx]` 이면 남은 어떤 A에 대해서도 `B[i] <= A[j]` 가 되어 이길 수 없다. **이 B는 버려도 손해가 없다.**

코드에서 `if (A[idx] < B[i])` 가 거짓일 때 `idx` 를 올리지 않고 `i` 만 넘어가는 것이 곧 "이 B를 버린다"에 해당한다.

### 이길 수 있는 더 큰 B 대신 가장 작은 B를 써도 손해가 없는 이유

`b < b'` 이고 둘 다 `a` 를 이긴다면, **`b` 가 이길 수 있는 A의 집합은 `b'` 가 이길 수 있는 A의 집합에 포함된다** (`b > x` 이면 `b' > b > x`).
즉 `b` 로 할 수 있는 일은 `b'` 로 전부 할 수 있지만 그 반대는 아니다.
그러므로 지금 `a` 를 잡는 데는 더 약한 `b` 를 쓰고, 더 강한 `b'` 는 앞으로 나올 더 큰 A를 위해 아껴 두는 편이 절대 손해가 아니다.

### 교환 논증으로 그리디가 최적임을 보이기

A, B를 오름차순 정렬하고 `a` = 남아 있는 A 중 최솟값, `b` = `a` 를 이기는 남아 있는 B 중 최솟값이라 하자.
주장은 **"`b` 를 `a` 에 배정하는 최적해가 항상 존재한다"** 이다.
임의의 최적해 `O` 에서 `a` 를 이긴 카드를 `b'`, `b` 가 이긴 카드를 `a''` 라 두고 경우를 나눈다.

- **`O` 에 `(b', a)` 와 `(b, a'')` 가 모두 있는 경우** — 두 배정을 교환해 `(b, a)`, `(b', a'')` 를 만든다. `b` 의 정의상 `b > a` 이고, `b` 가 `a` 를 이기는 최솟값이므로 `b' >= b > a''` 이다. 두 쌍 모두 여전히 승리이므로 승수가 그대로다.
- **`b'` 는 `a` 를 이겼지만 `b` 는 아무도 이기지 못한 경우** — `b` 와 `b'` 의 자리를 교환한다. `(b, a)` 는 `b > a` 이므로 승리이고, `b'` 가 옮겨 간 자리는 원래 0승이었으므로 승수가 줄지 않는다.
- **`b` 는 `a''` 를 이겼지만 `a` 를 이긴 카드가 없는 경우** — `a` 와 `a''` 를 교환한다. `b > a` 이므로 여전히 1승이고, 원래 `a` 를 맡아 지고 있던 카드는 `a <= a''` 이므로 `a''` 에 붙어도 여전히 진다. 승수가 그대로다.
- **둘 다 아닌 경우** — `b` 를 `a` 에 붙이면 승수가 1 늘어나므로 `O` 가 최적이라는 가정에 모순이다. 즉 이 경우는 생기지 않는다.

어느 경우든 승수를 잃지 않고 "`b` 를 `a` 에 배정한 최적해"로 바꿀 수 있다.
한 쌍을 확정한 뒤 남은 카드에 같은 논증을 반복(귀납)하면 그리디가 만드는 해가 최적임이 보장된다.
앞의 첫 번째 항목이 여기서 "`b` 가 `a` 조차 못 이길 때 그 `b` 를 버려도 되는" 근거를 채워 준다.

### 왜 `<` 이고 `<=` 가 아닌가

동점은 승리가 아니기 때문이다. `<=` 로 잘못 쓰면 "전부 같은 값"(`{5,5,5}` vs `{5,5,5}`)이 0이 아닌 3이 되고,
"완전히 같은 배열"(`{1,2,3}` vs `{1,2,3}`)도 2가 아닌 3이 되어 바로 깨진다.
반대로 **동점이 섞였다고 답이 0이 되는 것도 아니다.** `{1,2,3}` vs `{1,2,3}` 은 B의 2가 A의 1을, B의 3이 A의 2를 이겨 2가 정답이다.
무승부를 버리는 처리와 포인터 전진이 함께 맞물려야 나오는 값이다.

| 기준 | A: 이중 반복문 | B: 정렬 + 포인터 (선택) |
| --- | --- | --- |
| 시간 복잡도 | `O(n^2)` | `O(n log n)` |
| 공간 복잡도 | `O(n)` (사용 여부 배열) | `O(1)` (정렬 제외) |
| `n = 10^5` 에서 | 약 `10^10` 번 → 시간 초과 | 약 `1.7 x 10^6` 번 → 통과 |
| 쓴 카드 관리 | `used` 배열 또는 `remove` 필요 | 포인터 전진으로 자동 처리 |
| 틀릴 여지 | 사용 여부 갱신 누락 | **비교 부호**(`<` vs `<=`)에 정확성이 걸림 |

## 회고

### 검증

| 입력 (A / B) | 기댓값 | 결과 |
| --- | --- | --- |
| `{5,1,3,7}` / `{2,2,6,8}` (문제 예제) | 3 | 통과 |
| `{5,6,7}` / `{1,2,3}` (모든 B 패배) | 0 | 통과 |
| `{10,10}` / `{1,9}` (B 최댓값 < A 최솟값) | 0 | 통과 |
| `{1,2,3}` / `{4,5,6}` (모든 B 승리) | 3 | 통과 |
| `{1,2,3}` / `{2,3,4}` (모든 B 승리, 1 차이) | 3 | 통과 |
| `{1,1,1,2}` / `{1,2,2,2}` (중복, 양쪽) | 3 | 통과 |
| `{5,5,5}` / `{5,5,5}` (중복, 전부 같은 값) | 0 | 통과 |
| `{3,3,3}` / `{1,4,4}` (중복, A만) | 2 | 통과 |
| `{1}` / `{1}` (동점, 원소 1개) | 0 | 통과 |
| `{1}` / `{2}` (동점 아님, 원소 1개) | 1 | 통과 |
| `{2,2,3}` / `{2,3,3}` (동점 섞임) | 2 | 통과 |
| `{1,2,3}` / `{1,2,3}` (완전히 같은 배열) | 2 | 통과 |
| `{1,5,5}` / `{2,2,6}` (큰 카드 아끼기) | 2 | 통과 |

경계 케이스를 이렇게 잡은 이유

- **동점 계열** — 비교를 `<` 로 두었는지 걸러낸다. `<=` 로 쓰면 "전부 같은 값"과 "완전히 같은 배열"이 즉시 깨진다.
- **큰 카드 아끼기**(`{1,5,5}` / `{2,2,6}`) — B의 6을 A의 1에 낭비하면 1점이 되는 배치다. 정렬 후 포인터 그리디가 실제로 최적인지 확인한다.
- **전패** — `idx` 가 한 번도 전진하지 않아 `answer` 가 0으로 남는지 확인한다.
- **전승** — 매 반복마다 `idx` 와 `answer` 가 함께 증가해도 `A[idx]` 가 범위를 벗어나지 않는지 확인한다. `idx <= i < A.length` 이므로 안전하다.

### 배운 점

- "A마다 이기는 B를 찾는다"에서 **"B를 훑으며 남은 A 중 최솟값과만 비교한다"** 로 뒤집으니 탐색이 사라졌다. 방향을 바꾼 것만으로 `O(n^2)` 이 `O(n log n)` 이 됐다.
- 정렬해 두면 "남은 것 중 최솟값"이 항상 포인터 위치라서, 자료구조를 추가하지 않고도 최솟값 질의를 `O(1)` 에 해결할 수 있다.
- 쓴 카드를 지우는 대신 **포인터를 전진시키지 않는 것으로 "버린다"를 표현**했다. 상태를 따로 들고 있지 않으니 갱신을 빠뜨릴 자리도 없다.
- 그리디는 동작이 단순한 만큼 "왜 최적인가"를 따로 증명해야 안심할 수 있다. 교환 논증으로 한 쌍씩 최적해로 바꿔 나가는 방식이 그 틀이 됐다.
