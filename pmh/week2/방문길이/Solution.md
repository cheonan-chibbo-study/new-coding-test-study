# 방문 길이

## 문제 분석

- `U D L R` 명령을 따라 -5 ~ 5 좌표 평면 위를 이동하고, **처음 지나간 길의 길이**를 센다.
- 세는 대상은 "점"이 아니라 "길(간선)"이다. 같은 칸을 다시 밟더라도 그 사이를 잇는 길이 새로우면 길이는 늘어난다.
- 명령이 좌표 밖으로 나가면 그 명령은 **무시**된다. 위치도 그대로, 기록도 하지 않는다.
- 길에는 방향이 없다. `(0,0) -> (0,1)` 과 `(0,1) -> (0,0)` 은 같은 길이므로 한 번만 세야 한다.

---
## 풀이 고민

### 자료구조/알고리즘 후보
- 선택지 A : 지나간 길을 배열/리스트에 저장하고, 이동할 때마다 전부 비교
- 선택지 B : 지나간 길을 `Set` 에 넣어 중복을 판정

### 선택지 A 설명

처음에는 지나간 길을 배열에 담아두고 이동할 때마다 순회하면서 이미 지난 길인지 비교하려 했다.
구현은 단순하지만 이동 한 번마다 지금까지 지난 길 전체를 훑어야 해서, 명령이 늘어날수록 비교 횟수가 누적으로 커진다.
비효율적이라고 판단해 다른 방법을 고민했다.

### 선택지 B 설명

"중복을 막는다"가 문제의 핵심이라는 걸 떠올리고 `Set` 을 선택했다.
길 하나를 문자열 키로 만들어 `Set` 에 넣으면 중복 판정이 탐색 없이 끝난다.

구현 흐름:
- 현재 좌표 `x, y` 와 이동 후 좌표 `nx, ny`, 그리고 지나간 길을 담을 `Set` 을 선언한다.
- `U D L R` 에 따라 `nx, ny` 를 더하거나 뺀다.
- `nx, ny` 가 좌표 밖이면 `continue` 로 그 명령을 통째로 건너뛴다. (위치도 바꾸지 않는다)
- 좌표 안이면 지나간 길을 `road1 = "x,y,nx,ny"`, `road2 = "nx,ny,x,y"` 두 방향으로 만든다.
- `road1` 이 `Set` 에 없으면 `road1`, `road2` 를 모두 넣고 `answer` 를 +1 한다.
- 마지막에 `x, y` 를 `nx, ny` 로 갱신한다.

## 최종 결정 및 근거

**선택지 B (Set + 문자열 키) 를 선택했다.**

### 왜 점이 아니라 길을 저장하는가

점 집합만 저장하면 `(0,0)` 에 도착했다는 사실만 남고 **어디서 왔는지**가 사라진다.
`(1,0) -> (0,0)` 과 `(-1,0) -> (0,0)` 이 같은 방문으로 뭉개지므로, `UDDU` 같은 입력에서 서로 다른 길을 같은 길로 착각한다.
그래서 시작점과 도착점을 함께 묶은 **간선**을 저장한다.

### 왜 양방향 두 개를 다 넣는가

`(0,0) -> (1,0)` 과 `(1,0) -> (0,0)` 은 같은 길이다.
`road1` 만 저장하면 되돌아올 때 같은 길을 새 길로 세게 된다.
그래서 넣을 때 `road2` 까지 함께 넣어, 어느 방향으로 들어와도 같은 길로 판정되게 만들었다.

### 왜 경계 밖 명령은 위치와 기록을 둘 다 건드리면 안 되는가

두 상태는 하나의 트랜잭션이기 때문이다.
이동은 "위치 갱신 + 간선 기록"이 한 쌍으로만 의미가 있고, 무시되는 명령은 그 쌍 전체가 일어나지 않은 것으로 취급돼야 한다.
위치만 바꾸면 이후 모든 좌표가 어긋난 채로 전파되고, 기록만 하면 지나가지도 않은 길이 세어진다.

### 키를 무엇으로 만들 것인가 - 문자열 / 튜플 / 정수 인코딩 비교

| 기준 | 문자열 `"x,y,nx,ny"` (선택한 방식) | record/튜플 `Edge(x, y, nx, ny)` | 정수 인코딩 |
| --- | --- | --- | --- |
| 키 생성 비용 | 이동마다 문자열 새로 만듦 (StringBuilder + char 복사) | 객체 1개 할당 (필드 4개) | 할당 없음, 시프트/OR 몇 번 |
| 해시 비용 | 문자열 길이에 비례 `O(L)` | 필드 4개 산술 `O(1)` | 값 자체가 해시 `O(1)` |
| 충돌 위험 | **구분자가 반드시 필요** - 없으면 `-1,0` 과 `-10` 이 같은 키가 됨 | 없음 (필드 단위 비교) | 없음 (비트폭만 맞으면 서로 다른 값은 서로 다른 키) |
| 가독성 / 디버깅 | 가장 좋음. 출력하면 바로 읽힘 | 좋음. 타입까지 안전 | 나쁨. 숫자를 다시 좌표로 풀어야 함 |
| 좌표 범위 의존 | 없음 | 없음 | **있음** - 범위가 바뀌면 비트폭을 다시 설계해야 함 |

입력 길이가 최대 500 이라 성능 차이가 결과를 가르지 않는다.
그래서 디버깅할 때 바로 읽히는 문자열 키를 골랐고, 대신 구분자 `,` 를 반드시 넣어 `-1,0` 과 `-10` 이 섞이는 문제를 막았다.

### 배운 점

- 문제를 "점 방문"으로 읽으면 틀리고 "간선 방문"으로 읽어야 맞는다. 무엇을 세는지부터 정확히 정의하는 게 먼저였다.
- 중복 제거가 필요한 순간에 `Set` 을 떠올린 판단은 맞았다. 다만 그때 "무엇을 키로 삼을지"가 실제 난이도였다.
- 무시되는 명령을 `continue` 로 한 번에 건너뛴 덕분에 위치와 기록이 어긋날 여지가 없었다.
