## 문제 분석

- A 팀 출전 순서 고정, B 팀 출전 순서 최적화하여 **B 팀 최대 승점** 구하기.
- 무승부는 점수 없음, 큰 숫자가 승리.
- 효율성 테스트 제한사항으로 배열 크기가 최대 100,000이므로 효율적인 매칭 알고리즘 필요.

---

## 풀이 고민
### 자료구조/알고리즘 후보
- 선택지 A: 이중 루프 기반 그리디 탐색
- 선택지 B: 정렬 및 투 포인터 활용 최적화

### 선택지 A 설명
- B 배열만 정렬 후, A의 원소마다 B를 처음부터 순회하며 아직 사용하지 않은 카드(`visited`) 중 이길 수 있는 가장 작은 값을 매칭하는 방식.
- 정확성은 만족하나, 시간 복잡도가 $O(N^2)$이 되어 효율성 테스트에서 시간 초과 발생함.

```cpp
// 선택지 A 코드
#include <string>
#include <vector>
#include <algorithm>

using namespace std;

int solution(vector<int> A, vector<int> B) {
    int answer = 0;
    sort(B.begin(), B.end());
    
    vector<bool> visited(B.size(), false);
    
    for(int i = 0; i < A.size(); i++){
        for(int j = 0; j < B.size(); j++){
            if(!visited[j] && A[i] < B[j]){
                visited[j] = true;
                answer++;
                break;
            }
        }
    }
    return answer;
}
```

### 선택지 B 설명
- A와 B 배열을 모두 오름차순으로 정렬한 뒤, 각각의 인덱스를 가리키는 포인터(`idx_A`, `idx_B`)를 두고 비교하는 방식.
- B가 이기면 두 포인터 모두 전진, 이기지 못하면 B 포인터만 전진하여 다음 카드를 확인하는 시뮬레이션 구현.

---

## 최종 결정 및 근거
**선택지 B 채택**
- 처음 구상한 선택지 A 방식은 시간 초과로 실패하여, 전체 배열을 1회만 순회하는 선택지 B(투 포인터)로 선회함.
- 정렬에 $O(N \log N)$, 탐색에 $O(N)$이 소요되어 대규모 데이터셋에서도 효율성 테스트를 완벽히 통과함.

---

## 회고
- 처음에는 A의 고정 순서 때문에 A 정렬을 배제했으나, 승점의 최댓값만 구하면 되므로 A를 정렬해도 무방하다는 점을 파악함.
- `if-else` 문을 통해 이기지 못하는 B 카드를 '버리는 카드'로 간주하고 `idx_B++`만 수행하는 논리가 핵심이었음.
- 중첩 루프를 단일 루프로 변환함으로써 시간 복잡도를 혁신적으로 줄이는 투 포인터의 효과를 체감함.
